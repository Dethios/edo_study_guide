\section{Availability Work Package and SOVT Closeout}

\subsection{Summary}
\begin{description}
  \item[\textbf{Availability work package.}] The \ac{awp} is the consolidated industrial work plan for a scheduled
        maintenance availability, integrating maintenance, modernization, repair, alteration, inspection, and
        support-record inputs into one executable package~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025}.
  \item[\textbf{Stage flow.}] The \ac{awp} matures through Baseline, Preliminary, Proposed, Approved, and Completed
        stages, with planning gates aligned to the availability type and timeline~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025,edo-4-2-2-cno-availability-execution-2025}.
  \item[\textbf{Planning compression.}] \ac{cmav} planning compresses the broader \ac{sra}/\ac{cno}-availability cycle,
        so integration, ship checks, execution review, and closeout actions occur closer to A-0~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025,edo-4-2-2-cno-availability-execution-2025}.
  \item[\textbf{SOVT closeout.}] A signed \ac{sovt} verifies installed system performance under normal-service
        conditions and supports formal alteration or ship-change closeout; an unsigned \ac{sovt} is residual
        acceptance, retest, and schedule risk~\autocite{TS9090-310}.
\end{description}

\subsection{Availability Work Package Requirements and Development Stages}
\begin{description}
  \item[\textbf{Current-source caveat.}] The current \ac{jfmm} landing page identifies COMUSFLTFORCOMINST 4790.3
        Rev E dated 2026-04-27; detailed public text available for this board-prep summary was checked against recent
        Rev D volume changes, so use chapter-level paragraph details with that caveat~\autocite{COMFLTFORCOMINST4790-3}.
  \item[\textbf{AWP definition.}] The \ac{awp} is the consolidated industrial work plan for a scheduled maintenance
        availability, combining maintenance, modernization, and repair requirements drawn from the \ac{cmp}/\ac{icmp},
        \ac{navsea}-authorized alterations, \ac{tycom}-authorized alterations/repairs/PMRs/baseline \acp{awp},
        pre-availability tests and inspections, \ac{csmp}, and Fleet Technical Support records~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025}.
  \item[\textbf{AWP stages.}] The \ac{awp} progresses through Baseline, Preliminary, Proposed, Approved, and Completed
        stages. Public text supports Preliminary \ac{awp} development about 12--14 months before start, Proposed
        \ac{awp} within two months after WDC/PRC, Approved \ac{awp} at PAC, and Completed \ac{awp} within six months
        after availability completion~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025}.
  \item[\textbf{Baseline owners.}] Baseline \ac{awp} owners are \ac{submepp} for submarines, \ac{surfmepp} for
        surface ships, and \ac{pms}~312C for aircraft carriers~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025}.
  \item[\textbf{Modernization bridge.}] For modernization work, \ac{awp} content and \ac{sovt} planning should trace
        back to the authorized \ac{scd}/\ac{ndenm} record and the \ac{rmmco}-ready installation package~\autocite{JFMM-VolVI-RevD-Chg5-2025,TS9090-310}.
\end{description}

\subsection{Planning Milestones and Availability Type Differences}
Planned milestones for \ac{sra} and other \ac{cno}-scheduled availabilities establish early schedule alignment, work package integration, and contracting actions, with key gates at roughly A-720 (availability schedule), A-360 (letter of authorization), A-220 (work package integration conference), A-165 (100 percent work package lock letter), A-120 (contract award), and A-45 to A-30 (work package execution review) before A-0 start of availability.~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025,edo-4-2-2-cno-availability-execution-2025} By contrast, \ac{cmav} planning compresses the cycle, with planning beginning around A-180, integration and ship checks closer to A-60 to A-20, and a shortened execution review near A-10 before A-0 start.~\autocite{COMFLTFORCOMINST4790-3,edo-4-2-1-cno-availability-planning-2025,edo-4-2-2-cno-availability-execution-2025} Both paths use progress conferences during execution and culminate in completion reporting and lessons learned capture after availability closeout.~\autocite{edo-4-2-2-cno-availability-execution-2025}

\subsection{System Operational Verification Test Definition and Significance}
\begin{description}
  \item[\textbf{Definition.}] The \ac{sovt} verifies that an installed alteration, ship change, or maintenance-affected
        system performs as intended under normal-service conditions~\autocite{TS9090-310}.
  \item[\textbf{Source caveat.}] The public NAVSEA TS9090-310G text supports this board-prep summary; check the
        current controlled technical specification before operational execution if a newer official revision supersedes
        the public copy~\autocite{TS9090-310}.
  \item[\textbf{Completion evidence.}] The alteration is not complete until the \ac{sovt} or stage testing is
        successfully executed and witnessed by Ship's Force, and test reports must be provided to Ship's Force, the
        \ac{nsa}, and the \ac{lma}. System integration testing is complete only after successful testing with Ship's
        Force witnessing and signoff~\autocite{TS9090-310}.
  \item[\textbf{PCD distinction.}] Because \ac{pcd} definitions vary by project, state the local definition first. In
        board terms, production completion is a readiness gate for checkout, not final alteration acceptance; completed
        or signed alteration records plus completed \ac{sovt} support \ac{ait} checkout and closeout~\autocite{edo-4-2-2-cno-availability-execution-2025,TS9090-310}.
\end{description}

\subsection{Signed and Unsigned System Operational Verification Tests}
A signed \ac{sovt} is a completed test plan that has been executed, witnessed, and recorded with results and discrepancies, enabling formal acceptance and closeout of the alteration.~\autocite{TS9090-310} An unsigned \ac{sovt} indicates the test was not fully executed or witnessed, or that discrepancies remain unresolved, which delays acceptance and introduces schedule risk through retesting or deferred closeout actions.~\autocite{TS9090-310}
